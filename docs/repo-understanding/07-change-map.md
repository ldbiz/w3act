# Change Map

A practical guide to where to look before making common changes.

---

## If I Need to Change Startup or Runtime Behaviour

**Likely files:**
- `app/Global.java` — controls what happens at startup (data import, role check, actor scheduling)
- `conf/application.conf` / `conf/docker.conf` — flags that drive startup branches (`application.data.import`, `application.activeCrawling`)
- `app/uk/bl/crawling/CrawlActor.java` — nightly document harvesting schedule and logic

**Caveats:**
- The CrawlActor schedule is hardcoded to midnight + 24h. Changing the frequency requires editing `Global.java`.
- Akka is managed by Play; do not create a separate `ActorSystem`.

---

## If I Need to Change Configuration

**Likely files:**
- `conf/docker.conf` — for Docker/production (add new env var references here)
- `conf/application.conf` — for defaults / development
- `conf/prod.conf.template` — for non-Docker production deployments
- `docker-compose.yml` — to expose a new env var to the container
- `app/uk/bl/Const.java` — if the config value is accessed via a constant

**Caveats:**
- Play configuration values are read lazily at runtime via `Play.application().configuration().getString(...)`. There is no central config bean; usages are scattered across controllers and `Scope.java`.
- In `docker.conf`, a missing required env var will cause a startup failure with a cryptic Play error — test env var injection before deploying.

---

## If I Need to Change Request Handling or Core Behaviour

**Likely files:**
- `conf/routes` — add or change URL patterns
- `app/controllers/` — the relevant controller for the area being changed
- `app/models/` — the Ebean entity if data shape changes
- `conf/evolutions/default/` — add a new numbered SQL file if the DB schema changes

**For Target-related changes specifically:**
- `app/controllers/TargetController.java` — CRUD, bulk import, flag management
- `app/models/Target.java` — domain logic, scope checks, licence status

**Caveats:**
- Route priorities matter: more-specific routes must appear before wildcards in `conf/routes`.
- Ebean model changes require a new evolution file; forgetting this will cause runtime SQL errors.
- The `AbstractController` base class provides shared helpers (collection/subject tree building, caching via EhCache) — check it before duplicating logic in a new controller.

## If I Need to Change the Scope / Legal-Deposit Logic

**Likely files:**
- `app/uk/bl/scope/Scope.java` — the full scope rule engine (TLD, GeoIP, WHOIS)
- `app/models/Target.java` — manual scope flag methods (`isUkHosting()`, `checkManualScope()`, `checkLicense()`, `isInScopeAllOrInheritedWithoutLicense()`)
- `GeoLite2-City.mmdb` — replace when a newer MaxMind database is available

**Tests to run after changes:**
- `LicenseInheritanceTest.java`
- `TopLevelDomainTest.java`
- `UkHostingTest.java`
- `UkRegistrationTest.java`

**Caveats:**
- WHOIS checks make live network calls. They are toggled by `Scope.WHOIS_ENABLED` and are typically disabled in tests.
- GeoIP results depend on the bundled `GeoLite2-City.mmdb` — the database is not updated automatically.

## If I Need to Change External Service Integration

**Likely files:**
- `app/controllers/WaybackController.java` — Wayback / CDX server queries
- `app/uk/bl/crawling/Crawler.java` — Wayback document harvesting
- `app/uk/bl/scope/EmailHelper.java` — SMTP email sending
- `app/uk/bl/scope/Scope.java` — WHOIS integration
- `conf/converter/convertPdfToHtml.sh` — pdftohtmlEX invocation
- `conf/docker.conf` — update the env var that points to the service

**For RabbitMQ / crawl queue changes:**
- `app/controllers/TargetController.java` — look for AMQP `ConnectionFactory` usage

**Caveats:**
- External service URLs are read directly from Play configuration at call time — there is no centralised service registry or client class.
- The pdftohtmlEX integration uses a shell script (`conf/converter/convertPdfToHtml.sh`) rather than a direct HTTP call from Java.

---

## If I Need to Change UI / Templates / Static Assets

**Likely files:**
- `app/views/` — Twirl `.scala.html` templates; one subdirectory per domain area
- `app/views/main.scala.html` — global page layout wrapper
- `app/views/header.scala.html` — navigation bar
- `public/` — static JS, CSS, and image assets
- `conf/messages.en` / `conf/messages.cy` — UI string translations

**Caveats:**
- Twirl templates are compiled at build time. A template syntax error will fail the build.
- Welsh (`cy`) translations are partial — `conf/messages.cy` may have gaps for newer features.
- JavaScript routes are generated by Play and exposed at `/act/assets/javascripts/routes`. If you add or rename routes, regenerate the routes JS by restarting the app.

---

## If I Need to Change Tests or Fixtures

**Likely files:**
- `test/` — JUnit test classes
- `test/bdd/features/` — Gherkin feature files
- `test/bdd/step_definitions/` — Cucumber step definitions
- `conf/testdata-*.yml` — YAML fixture data (loaded by `DataImport`)

**Caveats:**
- Tests run sequentially (parallel execution is disabled). Tests that modify shared database state must clean up after themselves.
- Adding a new fixture entity requires a corresponding YAML fixture file and a corresponding `DataImport` method to load it.
- BDD tests using `HtmlUnit` require a running Play application; they are integration tests, not unit tests.
